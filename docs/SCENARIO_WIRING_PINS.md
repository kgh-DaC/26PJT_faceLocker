# 작동 시나리오 · 회로 배선 · 라즈베리파이 핀 할당 (사물함 4개 + 리밋센서)

- 기준: `docs/INTERFACES.md` v1.5 (§13·§15·§16), `configs/default.yaml`
- 상태: **계약 기준 문서**. 구현(hw/vision)은 진행 중이므로 코드 완료 후 `hw_selftest`로 재확인할 것.
- 대상: Raspberry Pi 5 / Ubuntu 24.04, 웹캠, 릴레이 4채널, 솔밸브 4개, 리밋센서 4개, LED 3개

## 1. 작동 시나리오

### 1.1 화면 구성
```
┌──────────────────────────────┬──────────────────┐
│                              │ [1] 닫힘 (잠김)   │
│        웹캠 영상             │ [2] 열림          │
│   (얼굴 박스·이름·점수)       │ [3] 닫힘 (잠김)   │
│                              │ [4] 닫힘 (잠김)   │
├──────────────────────────────┴──────────────────┤
│ 상태줄: 인식 문구 · FPS                          │
└─────────────────────────────────────────────────┘
```
- 사물함 패널: 큰 배지로 **열림/닫힘**, 부가로 잠김까지 카운트다운, 센서 오류 표시.
- 리밋센서 의미: **눌림 = 문 닫힘, 안 눌림 = 문 열림.**

### 1.2 사물함 상태 (LockerState)
| 상태 | 솔밸브 | 의미 |
| --- | --- | --- |
| LOCKED_CLOSED | OFF | 평상시. 문 닫힘+잠김 |
| UNLOCKED_WAITING | ON | 인식 성공으로 해제됨, 문이 열리기를 기다리는 중 |
| OPEN | ON | 문이 열려 있음. 닫힐 때까지 해제 유지 |
| CLOSING_CONFIRM | ON | 리밋이 눌려 닫힘 확인 중(연속 눌림 시간 측정) |
| COOLDOWN | OFF | 잠근 직후 재개방 최소 간격 |
| LOCKED_OPEN | OFF | 해제 없이 문이 열려 있음(강제 개방/방치) |
| SENSOR_FAULT | OFF | 리밋 읽기 실패. 해제 거부 |
| FAULT | OFF | 기타 오류(워치독 등) |

### 1.3 정상 시나리오
1. 사용자가 카메라 앞에 선다 → 얼굴 검출·품질 검사·임베딩·투표(5프레임 중 3회 일치).
2. 본인으로 판정 → 해당 사람의 `locker_id` 사물함에 해제 요청.
3. 해제 직전 리밋을 다시 읽는다. 문이 이미 열려 있거나 읽기 실패면 **해제 거부**(로그 `door_open` / `sensor_fault`).
4. 솔밸브(릴레이) ON, 초록 LED ON, 상태 `UNLOCKED_WAITING`.
5. 사용자가 문을 열면 리밋이 해제(open_confirm 0.1초 연속) → `OPEN`, 패널 "열림". **문이 닫힐 때까지 솔밸브 ON 유지.**
6. 사용자가 문을 닫으면 리밋 눌림 → `CLOSING_CONFIRM`. **`close_confirm_sec`(2.0초) 연속** 눌림이 유지되면 솔밸브 OFF → 잠금 → `COOLDOWN` → `LOCKED_CLOSED`.
7. 닫힘 확인 중 문이 다시 열리면 카운터 리셋, 솔밸브는 그대로 ON(채터링 방지).

### 1.4 예외 시나리오
| 상황 | 동작 |
| --- | --- |
| 해제했지만 문을 안 연다 | `unlock_timeout_sec`(10초) 후 자동 재잠금 |
| 문을 연 채 오래 방치 | 열림 유지. 단 `max_unlock_sec`(30초) 워치독이 해제 시점 기준으로 잠금(문은 열린 채 `LOCKED_OPEN`) |
| 리밋 선 빠짐/센서 고장 | 해제 요청은 거부. 해제 중이면 `sensor_fault_sec`(1초) 후 즉시 잠금 |
| 미등록 얼굴/판정 보류 | 개방 안 함. 빨강(거부)/노랑(보류) LED |
| 카메라 오류·프로그램 종료 | 모든 출력 OFF(잠금) 후 종료, systemd가 재시작 |
| 메인 루프(카메라/화면) 정지 | 상태기계는 하드웨어 스레드가 구동하므로 재잠금이 지연되지 않음 |
| 동시 개방 | `max_concurrent_open`(기본 1)까지만 |

### 1.5 PC mock 시험
- 가상 리밋: 패널 클릭 또는 키 **1~4**로 문 열림/닫힘 토글, 키 **5~8**로 센서 실패 주입. 실기에서는 무시됨.
- 위 시나리오가 실제와 동일한 상태기계를 거친다.

> 핀 충돌 없음: 위 BCM 번호 12개는 서로 겹치지 않는다. 단, 리밋 핀 5/6/12/13은 **설계 에이전트의 제안값**이며 실배선 후 `configs/local.yaml`로 확정한다.
> 웹캠은 USB 포트 사용(GPIO 불필요). Pi5는 `pin_factory: lgpio` 필수.

### 2.1 `configs/local.yaml` 예시
```yaml
hardware:
  mode: pi
  solenoid_pin: null
  solenoid_active_high: true      # active-LOW 릴레이 보드면 false (잘못 쓰면 시작 즉시 전부 열림!)
  max_concurrent_open: 1
  close_mode: limit
  limit_pull_up: true
  limit_active_low: true          # NO 접점 + GND 배선. NC 접점 배선이면 false
  close_confirm_sec: 2.0
  unlock_timeout_sec: 10.0
  max_unlock_sec: 30.0
  sensor_fault_sec: 1.0
  locker_outputs:
    - {locker_id: "1", pin: 24, limit_pin: 5}
    - {locker_id: "2", pin: 25, limit_pin: 6}
    - {locker_id: "3", pin: 16, limit_pin: 12}
    - {locker_id: "4", pin: 26, limit_pin: 13}
lockers:
  mode: per_locker
  allow_shared: false
```

## 3. 회로 배선

### 3.1 전체 블록도
```
 [USB 웹캠] ───────────────► Raspberry Pi 5 (Ubuntu 24.04)
                                   │ GPIO (3.3V 로직)
        ┌──────────────────────────┼───────────────────────────┐
        │                          │                           │
  릴레이 모듈(4ch)           리밋센서 ×4                  LED ×3 (+저항)
  IN1..IN4 ← BCM24/25/16/26   BCM5/6/12/13 ↔ GND         BCM27/22/23
        │
  릴레이 접점 COM/NO
        │
  외부 전원(솔밸브 정격, 예 12V/24V DC) ── 솔밸브 ×4 (각각 역기전력 다이오드)
```
**솔밸브 전원은 반드시 Pi와 별도 전원**(GND는 릴레이 모듈 절연 사용). Pi 5V/3.3V 핀에서 솔밸브를 직접 구동하지 않는다.

### 3.2 솔밸브 + 릴레이 (사물함 1개 기준, 4개 동일)
```
Pi BCM24 ──► 릴레이 IN1        릴레이 VCC ◄ Pi 5V(핀2)    릴레이 GND ◄ Pi GND
외부 + ──► 릴레이 COM1
          릴레이 NO1 ──► 솔밸브 (+)
                         솔밸브 (−) ──► 외부 −
솔밸브 양단에 플라이백 다이오드: 캐소드(띠) → (+), 애노드 → (−)  (DC 솔밸브 필수)
```
- 접점은 **NO(상시 열림)** 사용 → 전원/Pi 꺼지면 솔밸브 OFF = 잠금.
- 릴레이 모듈의 로직 입력이 3.3V 호환인지, **부팅 중 핀이 HIGH/LOW 어느 쪽인지** 확인(active-LOW 보드는 `solenoid_active_high: false`).
- 솔밸브는 문이 열려 있는 동안 **연속 통전**된다. 정격 듀티가 `max_unlock_sec`(30초) 이상인지 확인. 부족하면 값을 줄이거나 연속 정격 제품 사용.
- 솔밸브 전류에 맞는 릴레이 접점 정격(예: 24V DC 2A 이상)과 퓨즈를 사용.

### 3.3 리밋센서 (사물함 1개 기준)
Pi 내부 풀업 사용(외부 저항 불필요). 센서의 한 선은 GPIO, 다른 선은 GND.
```
        ┌── Pi BCM5 (물리29)   (내부 풀업 → 평소 HIGH)
리밋 ──┤
        └── Pi GND (물리30 등)
```
| 배선 | `limit_active_low` | 눌림(문 닫힘) | 안 눌림(문 열림) | 선 끊김 |
| --- | --- | --- | --- | --- |
| **NO 접점** + GND | `true` (기본) | LOW | HIGH | HIGH → "열림"으로 읽힘 → 해제 거부/워치독이 방어 |
| **NC 접점** + GND (**권장**) | `false` | HIGH | LOW | HIGH → "닫힘"으로 읽힘 → 잠금 쪽(안전) |

- NC 배선 시: 문이 닫혀 눌리면 NC 접점이 열려 GPIO HIGH(닫힘), 문이 열리면 접점이 닫혀 GND로 LOW(열림).
- 선이 길면(약 1m 이상) 실드선/트위스트 사용, 센서 선과 솔밸브 전원선을 분리. 채터링은 소프트웨어(`open_confirm_sec` 0.1 / `close_confirm_sec` 2.0)로 처리.
- 센서는 문이 닫힐 때 확실히 눌리도록 기구적 위치를 조정(반쯤 닫힘이 "닫힘"으로 읽히면 잠금 시 걸림 발생).

### 3.4 LED (3개)
```
BCM27 ──[330Ω]──►|── GND   (초록, 개방 중)
BCM22 ──[330Ω]──►|── GND   (빨강, 거부)
BCM23 ──[330Ω]──►|── GND   (노랑, 판정 보류)
```
(애노드 쪽에 저항, 캐소드는 GND)

## 4. 안전 및 시험 순서
1. **솔밸브 전원을 분리**한 상태로 시작한다(극성 설정 오류 시 시작 즉시 전 사물함이 열릴 수 있음).
2. `hardware.mode: mock`으로 PC 시뮬레이션 시나리오(1.3, 1.4) 확인.
3. Pi에서 `scripts/hw_selftest.py`로 릴레이 소리/LED, 리밋 입력(눌렀다 뗐을 때 로그) 개별 확인. 부팅·재부팅 시 릴레이가 꺼져 있는지 확인.
4. 솔밸브 전원 연결 후 시나리오 1.3(정상), 1.4(문 미개방 재잠금, 선 뽑기 → 센서 오류, 방치 → 워치독)을 순서대로 시험.
5. 서비스 자동 시작은 배선 검증 이후에 켠다.

## 5. 확인 필요 항목
- 리밋 접점 종류(NO/NC) 및 `limit_active_low` 값
- 릴레이 모듈 극성(active-HIGH/LOW)과 3.3V 호환 여부
- 솔밸브 정격 전압/전류, 연속 통전 정격(30초 기준)
- `unlock_timeout_sec` 10초, `max_unlock_sec` 30초, `close_confirm_sec` 2초는 제안 기본값
- 리밋 핀(5/6/12/13) 확정 여부
- 위조(사진/영상) 방어는 없음(`liveness: none`)
